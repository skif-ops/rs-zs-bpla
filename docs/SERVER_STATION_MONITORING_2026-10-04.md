# Сервер: страница «Станции» — состояние станций по heartbeat (2026-10-04)

Код: `server/station/health.py` (оценка состояния), `station/health_api.py` (`GET /api/v1/stations/health`),
`templates/stations.html`, `static/js/stations.js`, `station/pki_registry.py` (реестр PKI, общий с каталогом панели
администрирования). Проверки: `server/tests/test_station_health.py`.

## 1. Что показывает

Страница `/stations` (пункт меню «Станции», право `read`) — таблица всех станций, которые видит учётная запись
(правила видимости — `docs/SERVER_ACCESS_CONTROL_2026-10-02.md`, §6), по последнему heartbeat каждой:

| Столбец | Откуда |
|---|---|
| станция, серийный номер, участок | номер из heartbeat; серийный номер и партия — из реестра PKI (`registry.sqlite3`); участок — мост, через который станция выходила на связь, иначе участок партии |
| состояние | «на связи», «опаздывает», «потеряна» по молчанию (§2); «не выходила» — станция реестра без единого heartbeat |
| heartbeat | сколько времени назад сервер получил последний heartbeat (по часам сервера; часы станции в подсказке) |
| батарея, солнце, t | `power`: заряд и напряжение батареи, напряжение панели, температура |
| GNSS, время | `gnss`: фиксация, спутники, PPS; доверие ко времени |
| связь | `route`: транспорт и RSSI; оператор из `cellular` |
| прошивка, модель, работает | `firmware_ver` и `fw_version` с состоянием обновления, `model_ver`, `uptime_s` |
| требует внимания | проблемы §3 |

Сверху сводка: всего, на связи, опаздывают, потеряны, не выходили, тревога, внимание, низкий заряд, GNSS/время/положение,
обновляются. Нажатие на карточку фильтрует таблицу, заголовок столбца сортирует (повторно — в другую сторону), поле
под заголовком фильтрует по подстроке; фильтры складываются. Нажатие на строку раскрывает все поля heartbeat
(станция и положение, связь, питание, GNSS, версии, детектор) и сам heartbeat в JSON. Идентификаторы абонента
(IMSI, ICCID) показаны усечёнными, как и везде на сервере. Данные перечитываются раз в минуту и при возврате на
вкладку; живого потока для heartbeat нет (они приходят через мост MQTT — отдельный процесс).

## 2. Молчание

Период heartbeat в дежурном режиме — 6 часов (`heartbeat_period_s`, ICD аддендум D; в сеансе после события — раз в
минуту). Пороги задаются переменными окружения сервера (compose) и меняются без пересборки:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ZS_STATION_LATE_S` | 25200 (7 ч) | дольше — «опаздывает» (уровень «внимание») |
| `ZS_STATION_LOST_S` | 46800 (13 ч) | дольше — «потеряна» (уровень «тревога»); не меньше `ZS_STATION_LATE_S` |
| `ZS_STATION_BATTERY_LOW_PCT` | 20 | ниже — «низкий заряд» («внимание»; ниже половины порога — «тревога») |

Молчание считается по времени получения heartbeat сервером (`received_us` в таблице `stations`; у строк, записанных
до этого столбца, берётся время станции `updated_us`).

## 3. Что требует внимания

Уровни: «тревога» (нужен выезд или решение), «внимание» (наблюдать), «информация» (нормальное переходное
состояние). Уровень строки — худший из молчания и проблем; по нему сортируется столбец «Состояние».

| Код | Уровень | Условие |
|---|---|---|
| `battery_low` | внимание / тревога | заряд ниже порога / ниже половины порога |
| `temperature` | внимание | температура вне −30…+60 °C |
| `self_test`, `fault:<флаг>` | тревога | `self_test_ok` ложь; каждый флаг `fault_flags` |
| `selftest_failed` | тревога | битовая маска `selftest_failed_tests` (имена тестов прошивки по битам) |
| `gnss_spoof`, `gnss_jam` | тревога | подмена, помеха |
| `position_suspect` | тревога | `position_suspect` или доверие к положению SUSPECT / REVALIDATION_REQUIRED |
| `position_warn` | внимание | `position_warn` или доверие CONFIGURED_WARN (уход на `position_delta_m`) |
| `time_suspect`, `time_unsynced` | тревога | время сомнительно / не синхронизировано |
| `time_holdover`, `gnss_no_fix` | информация | удержание времени, нет фиксации на момент heartbeat: обычное состояние станции, проснувшейся из дежурного режима |
| `watchdog_reset`, `watchdog_missed` | внимание | причина перезагрузки IWDG/WWDG; пропущенные задачи watchdog |
| `outbox` | информация / внимание | недоставленные сообщения: до 10 / от 10 |
| `fw_rolled_back`, `net_rolled_back` | тревога | откат прошивки / сетевой настройки |
| `fw_update`, `net_trial` | информация | обновление или сетевая настройка на проверке |

Слабый сигнал, потерянные окна детектора и отсутствие PPS намеренно не поднимаются как проблемы (приоритет заказчика —
минимум ложных тревог): они видны как значения.

## 4. API

`GET /api/v1/stations/health` → `{"now_us", "thresholds": {late_s, lost_s, battery_low_pct}, "summary": {total, online,
late, lost, never, alarm, warn, battery_low, gnss, updating}, "stations": [...]}`; каждая станция: идентификация
(`station_id`, `serial`, `lot`, `tenant`, `registry_status`), `state`, `level`, `silence_s`, `received_us`, `time_us`,
`problems: [{code, level, text}]`, разделы `power`, `gnss`, `route`, `cellular` (усечённые идентификаторы), `versions`,
`detector`, `position`, `self_test_ok`, `fault_flags` и `heartbeat` целиком. Ограниченная учётная запись получает только
свои станции; `GET /api/v1/stations` (сырые heartbeat) без изменений.

## 5. Меню

Главное меню перестроено по видам работы: «Станции», «Сопровождение» (работа с сетью) | «Один файл», «Локализация»,
«Обучение» (анализ записей) | «Администрирование» (по правам). Открытый раздел выделен; главная страница делит
карточки на те же группы.
