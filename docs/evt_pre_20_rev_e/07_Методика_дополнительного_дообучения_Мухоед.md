# Методика дополнительного дообучения Мухоеда

Редакция: Rev E от 06.10.2026.

## 1. Цель

Методика применяется для добавления подтвержденных типов и условий записи без ухудшения обнаружения, классификации и ложных тревог на существующих данных.

## 2. Запрет на неподтвержденные данные

Запись включают в обучение только при известном источнике, времени, месте, типе объекта, режиме полета, расстоянии или траектории, конфигурации станции и лицензии на использование. Неподтвержденные записи остаются исследовательскими и не получают рабочую метку точного типа.

## 3. Сбор данных

Для каждого типа собирают несколько экземпляров, расстояний, азимутов, высот, скоростей, режимов двигателя, ветра и фоновых условий. Отдельно собирают отрицательные примеры: транспорт, генераторы, речь, птицы, дождь, ветер, промышленный шум и тишину.

## 4. Реестр происхождения

| Поле | Требование |
|---|---|
| source_id | Уникальный идентификатор исходной записи |
| sha256 | Контрольная сумма неизменного файла |
| target | Подтвержденный тип или UNKNOWN |
| date_time | UTC и локальная зона |
| station | Serial и версия конфигурации |
| geometry | Координаты станции и траектория цели |
| weather | Ветер, осадки, температура |
| rights | Основание использования |
| reviewer | Кто подтвердил метку |

## 5. Разделение выборок

Разделять train, validation и test по исходным полетам и физическим объектам, а не по соседним окнам одной записи. Один полет не должен попадать в разные части. Финальный test фиксируется до обучения и не применяется для подбора параметров.

## 6. Подготовка

Проверить частоту дискретизации, количество каналов, клиппинг, временную синхронизацию и целостность. Сохранить исходный файл неизменным. Производные окна получают ссылку на source_id, время начала и параметры обработки.

## 7. Обучение

Сначала воспроизвести baseline текущей модели на закрепленном окружении. Затем обучить кандидата тем же конвейером, добавив новые данные. Зафиксировать Git commit, версии зависимостей, seed, конфигурацию, список SHA-256 источников, метрики и итоговый бинарный пакет.

## 8. Метрики

Сравнить Pd по классам и дальностям, precision, recall, матрицу ошибок, false alarms на station-hour, калибровку confidence и устойчивость по шумам. Отдельно проверить UNKNOWN для известных семейств, но неподтвержденных точных типов. Нельзя принимать модель только по росту средней accuracy.

## 9. Приемка

Кандидат проходит offline test, replay подтвержденных полетов, quiet periods, цифровые двойники и затем ограниченный canary на стендовой станции. Ухудшение критических классов или рост ложных тревог выше утвержденного предела означает FAIL. Пределы фиксируются в программе испытаний до открытия test set.

## 10. Выпуск

Экспортировать модель командой `tools/export_station_model.py`, проверить manifest и target, подписать offline release key командой `model-sign`, поместить в серверный репозиторий моделей. Сначала обновить стендовую станцию, затем canary, затем волну. Сервер должен показывать новую версию модели в heartbeat.

## 11. Rollback

Сохранить предыдущий подписанный пакет. При росте ошибок, rollback станции или несовместимости остановить rollout. Возврат выполняют выпуском предыдущего содержимого с новой монотонной версией, если протокол запрещает уменьшение версии.

## 12. Отчет

Отчет содержит цель, состав данных, исключения, provenance, конфигурацию, baseline, метрики кандидата, интервалы неопределенности, результаты replay/canary, известные ограничения, решение и подписи. Без этого модель остается исследовательской.
