# Пеленг решётки 3+1: оценка апертуры, накопления и ветрозащиты (2026-09-30)

Повод: сравнение с комплексом ZVOOK Tracking / «Звук» (решётки с апертурой около 0,5 м, пеленг по сетке 5°,
две решётки на базе 50 м). Вопрос: хватает ли зафиксированной геометрии Дионеи (DEC-005: треугольник 120 мм,
MIC4 на +150 мм, наибольшая база 0,165 м) и что даёт увеличение апертуры.

## Находка

До этой ревизии пеленгатор `zs_spatial` (GCC-PHAT и решатель 3+1) был покрыт тестами, но в конвейер станции не
подключён: анализировался один канал, блоки DOA (ключ 11) и TDOA (ключ 14) события оставались пустыми. Теперь
пеленг считается на борту (`zs_bearing`, `zs_station_pipeline`) для каждого окна уровня CONFIRMED.

## Методика

`tools/array_bearing_mc.py` собирает из исходников прошивки `zs_spatial.c` и `zs_fft.c` и прогоняет Монте-Карло
тем же кодом, что работает на станции. Сигнал: поршневой БПЛА (f0 около 110 Гц, гармоники до 2,5 кГц, спад
k^-0,7), плоская волна с дробными задержками, некоррелированный шум на каждом микрофоне при заданном ОСШ в полосе;
ветровой шум моделируется некоррелированным 1/f^2 ниже 60 Гц. Направления случайные: азимут 0–360°, угол места
5–45°. Кадр 1024 отсчёта (32 мс при 32 кГц), полоса 80–3000 Гц; оценка по одному кадру или медиана задержек по
N кадрам.

## Выводы

- Накопление медианой по 8–16 кадрам улучшает точность в 3–4 раза, столько же даёт увеличение апертуры вчетверо.
  Геометрию не меняем: 1–2° при ОСШ 0 дБ дают 20–35 м поперёк направления на 1 км, у ZVOOK шаг сетки 5°.
- Нижний предел задаёт ОСШ: при −12 дБ большая апертура не спасает, доля отказов растёт (шире окно поиска
  задержек). Поэтому пеленг считается только для окон CONFIRMED.
- Допуск установки микрофонов ±1 мм даёт около 0,5° систематики, это в бюджете.
- На борту: 8 кадров по 1024 отсчёта из последних 0,5 с окна, одно преобразование опорного канала на кадр
  (4 БПФ + 3 обратных), кадр отбрасывается при когерентности PHAT ниже 0,25 (независимый шум 0,1–0,2), нужно не
  менее 4 кадров. Оценка загрузки МК: порядка 10% при пеленге каждые 0,5 с; точная цифра будет после замера на
  NUCLEO/Rev.A (`window_max_ms`, `pipeline_max_ms`).
- Скорость звука берётся при 15 °C (датчика температуры воздуха у приложения нет); на азимут это почти не
  влияет, на угол места при −20 °C даёт до 2–3°. Подключение внутреннего датчика открыто.

## Ветрозащита: что проверить на EVT

Модель не заменяет замер: реальный ветровой шум на MEMS захватывает сотни герц. Рекомендация для корпуса: слой
ретикулированного поролона 15–25 мм (10–20 PPI) поверх отверстий микрофонов под рёбрами «тарелки» и «юбки».
Проверка: два изделия рядом, одно с поролоном и одно без; спектр шума 20–500 Гц и когерентность каналов при
разном ветре (скорость ветра из внешнего сервиса); критерий: доля кадров с когерентностью выше 0,25 при пролёте и
ошибка пеленга относительно видеофиксации или GNSS-трека тестового БПЛА.

## Проверка в репозитории

- `firmware/tests/test_bearing.c`: общий опорный канал совпадает с попарным расчётом; пеленг плоской волны с
  шумом в пределах 5° по азимуту и 6° по углу места для шести направлений; шум без источника пеленга не даёт;
  путь из кольца, границы кольца; событие несёт DOA и TDOA, азимут 0..35999 сотых градуса.
- Двойник: источник рендерится плоской волной на решётку по направлению сегмента сцены (`firmware/twin/array_render.c`),
  фон независим по микрофонам; сценарий 1 `server/tools/test_station_twin_e2e.py` проверяет, что DOA события,
  разобранный сервером, в пределах 5° от истинного направления.
