# ICD GSM/LTE MQTT/TLS v0.1 — Addendum D: CMD_REBOOT and CMD_SET_PARAMS (2026-09-25)

Статус: DRAFT. Расширяет §2.1 (подписанный конверт команды) двумя кодами. Конверт, подпись Ed25519, TTL ≤ 15 мин,
dedup по `command_id`, журнал `ACCEPTED → COMPLETED` и ACK (§2.2) — без изменений. Обоснование — в
`docs/REMOTE_OPERATIONS_ANALYSIS_2026-09-25.md`.

## 1. Коды

| Код | Имя | Ключ 7 (payload) |
|---:|---|---|
| 1 | `CMD_REQUEST_AUDIO` | §2.1 (без изменений) |
| 2 | `CMD_REBOOT` | `{0: delay_s}` — uint 0..600 |
| 3 | `CMD_SET_PARAMS` | `{0: reset_to_defaults (bool), 1: {param_id: int32, ...}}` — 0..8 параметров, id по возрастанию (канонический CBOR), пусто только при `reset_to_defaults = true` |

## 2. Параметры `CMD_SET_PARAMS`

| id | Имя | Диапазон | По умолчанию | Что меняет на станции |
|---:|---|---|---:|---|
| 1 | `heartbeat_period_s` | 900..86400 | 21600 | период выхода S0 → S3 ради heartbeat |
| 2 | `mic_channel` | 0..3 | 0 | канал микрофона, который анализирует детектор (обход отказавшего) |
| 3 | `event_update_windows` | 4..40 | 10 | период обновления события, окон по 0,5 с |
| 4 | `comms_degraded_after` | 1..10 | 3 | неудачных сессий S3 до признания GSM деградированным |
| 5 | `gsm_probe_s` | 300..14400 | 1800 | период пробы GSM в деградированном режиме |
| 6 | `listen_dwell_s` | 1..10 | 3 | предельное время S1 без решения шлюза |

Сервер (`station/command_codec.py`, `STATION_PARAMS`) и станция проверяют таблицу независимо. Неизвестный id или
значение вне диапазона отклоняет **всю** команду, ничего не применяется. `reset_to_defaults` сначала возвращает все
параметры к умолчаниям, затем применяет перечисленные. Применённые параметры хранятся в NOR (A/B-запись в двух
последних блоках раздела образа nRF: раздел 128 блоков, вторичному слоту MCUboot нужно 119; ёмкость образа
ограничивается 126 блоками) и переживают перезагрузку. Хеш применённого набора входит в heartbeat.

## 3. Исполнение и ACK

| Команда | Исполнение | ACK |
|---|---|---|
| `CMD_REBOOT` | журнал `COMPLETED`, ACK публикуется, сброс через `max(delay_s, 5)` с после ACK | `OK`, detail 0 |
| `CMD_SET_PARAMS` | проверка всей таблицы → запись NOR → применение → журнал `COMPLETED` | `OK` detail 0; `REJECTED` detail `0x0100 \| param_id` (неизвестный/вне диапазона); `FAILED` detail 1 (NOR) |

Повторная доставка после перезагрузки (QoS 1) находит `COMPLETED` в журнале и повторяет сохранённый ACK без второго
сброса. Тот же `command_id` с другим содержанием — `CONFLICT` (отпечаток журнала покрывает `delay_s` и список
параметров; отпечаток `CMD_REQUEST_AUDIO` не изменился, записи на NOR остаются валидными).

## 4. Кросс-вектор

`tools/generate_command_set_vector.py` → `firmware/generated/zs_command_set_vector.h`: `CMD_REBOOT` (delay 30 с) и
`CMD_SET_PARAMS` (`heartbeat_period_s` 3600, `mic_channel` 2, `listen_dwell_s` 5), подписанные серверным кодеком
тестовым ключом репозитория. Прошивка (`firmware/tests/test_command_set.c`) проверяет подпись настоящим Ed25519,
поля, отказ при порче любого байта и семантику журнала; сервер (`server/tests/test_command_set_codec.py`) —
актуальность заголовка, диапазоны и отказы.
