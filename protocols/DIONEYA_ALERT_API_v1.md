# Выходной API оповещений `dioneya.alert/1` (2026-09-30)

Статус: DRAFT. Решение п.7 сравнения с ZVOOK (`docs/ZVOOK_COMPARISON_DECISIONS_2026-09-30.md`): внешним системам
сервер отдаёт собственную версионированную JSON-схему. Каналы: HTTP-опрос, подписка WebSocket, вебхук HTTPS с
взаимным TLS. Подписка MQTT и адаптер EGTS для Платформы — следующими шагами, в той же схеме сообщений. Схема для
проверки: `protocols/schemas/dioneya.alert.1.schema.json`. Код: `server/integration/` (`dioneya_alert.py`,
`alert_producer.py`, `webhook.py`), выдача — `server/station/router.py`.

## 1. Что передаётся

| Сущность | Сообщения | Когда |
|---|---|---|
| тревога (эпизод) | `alert.start`, `alert.update`, `alert.end` | начало — первое событие, пеленг или трек арендатора (`tenant`), пока открытой тревоги нет; обновление — вырос уровень, добавилась станция или трек, уточнился класс; конец — 120 с без активности |
| трек цели (точка по двум и более станциям) | `track.update`, `track.end` | обновление — новая точка трека, не чаще 1 Гц (сетка слияния 1 с); конец — слияние трека не обновлялось 20 с (`end_reason: "lost"`) или закончилась тревога (`"alert_end"`) |
| пеленг одиночной станции | `bearing` | пока трек станции не вошёл в трек цели: последний пеленг, не чаще 1 Гц на станцию; линия от станции длиной `range_max_m` |
| живость канала | `heartbeat` | канал простаивает (WebSocket — 15 с по умолчанию, вебхук — 60 с); не хранится |

Уровень тревоги: `warning` — цель слышит одна станция, `alert` — две и больше станций или есть трек цели. После
`track.end` сообщений по этому `track_id` больше нет (конец — позже, чем окно присоединения треков станций, 15 с).
Пеленги и точки передаются только при доверенном времени станции (GNSS или удержание): без него направление нельзя
привязать ко времени.

Точка трека считается по пеленгам нескольких станций с учётом времени распространения звука
(`protocols/MQTT_TLS_ICD_v0_1_ADDENDUM_H_BEARING_STREAM.md`, §4.1). Треки станций, которые слышат разные цели (разный
известный класс или основная частота дальше, чем допускает доплеровский сдвиг между станциями, в 1,45 раза), не
сливаются: две цели одновременно не дают ложных пересечений их лучей (§4.1 аддендума H). Две цели одного класса с
близкой основной частотой разделить пока нельзя.

## 2. Сообщение

Один JSON-объект, UTF-8. Потребитель игнорирует неизвестные поля: новые поля внутри `dioneya.alert/1` добавляются
только необязательными и описываются новой редакцией JSON-схемы; несовместимое изменение — это `dioneya.alert/2`.

| Поле | Тип | Смысл |
|---|---|---|
| `schema` | строка | `"dioneya.alert/1"` |
| `seq` | целое | номер в очереди сервера: порядок выдачи, продолжение опроса и курсор вебхука; растёт, но не подряд (сообщения других арендаторов) |
| `msg_id` | строка | детерминированный идентификатор факта: повтор того же факта имеет тот же `msg_id`, потребитель отбрасывает повтор |
| `type` | строка | тип (§1) |
| `tenant` | строка | арендатор (группа станций, `zs/v1/{tenant}/...`); у `heartbeat` — фильтр канала или `null` |
| `alert_id` | строка | тревога, к которой относится сообщение (`ALR-{tenant}-{начало, мкс, hex}`); у `heartbeat` — `null` |
| `time` | время | к чему относятся данные: точка трека — момент излучения звука, пеленг — момент прихода звука на станцию, начало тревоги — первое свидетельство, конец — момент решения |
| `created` | время | когда сервер сформировал сообщение |
| `alert` / `track` / `bearing` | объект | тело по типу (§3) |

Время — UTC, RFC 3339 с миллисекундами (`2026-09-30T20:00:12.000Z`). Координаты — WGS-84, градусы; высоты — над
средним уровнем моря, м; направления — градусы по часовой от истинного севера; скорости — м/с.

## 3. Тела

`class` (в тревоге, треке и пеленге):

| Поле | Смысл |
|---|---|
| `code` | `uav_piston` (БПЛА с ДВС), `uav_jet` (реактивный БПЛА), `uav_electric` (БПЛА с электродвигателем), `aircraft`, `helicopter`, `other`, `unknown` |
| `label` | метка классификатора станции (`PISTON_UAV`, ...) |
| `confidence` | 0..1, уверенность лучшей классификации |
| `type` | тип изделия, когда классификатор типа уверен (`PROVISIONAL`/`STABLE`), иначе `null` |
| `f0_hz` | медиана основной частоты звука по станциям, Гц, или `null` |

`station`: `station_id`, `lat`, `lon`, `alt_msl_m` (координаты `null`, пока станция их не сообщила).

`alert`: `level` (`warning`/`alert`), `started`, `ended` (время или `null`), `stations` (массив `station`), `class`,
`tracks` (идентификаторы треков тревоги).

`track`:

| Поле | Смысл |
|---|---|
| `track_id` | `TRK-{наименьший track event_id}-{станция}`, неизменен |
| `position` | `lat`, `lon`, `alt_msl_m` точки |
| `error` | `horizontal_m` — радиальная ошибка 1σ (корень из суммы дисперсий по осям), `vertical_m` — 1σ по высоте |
| `velocity` | `speed_mps`, `course_deg`, `east_mps`, `north_mps`, `up_mps` |
| `class` | класс по станциям трека |
| `stations` | станции, чьи пеленги дали точку |
| `crossing_deg` | угол пересечения лучей (меньше 10° точки не бывает: слепая зона вдоль базы) |
| `first` | время первой точки трека |
| `points` | точек в треке |
| `ended`, `end_reason` | у `track.end`: время и причина (`lost`, `alert_end`); у `track.update` — `null` |

`bearing`: `station`, `track_event_id` (16 hex-цифр: трек станции), `azimuth_deg`, `elevation_deg`, `sigma_deg`
(1σ), `range_max_m` (длина линии, 5000 м — дальность слияния), `class`.

Пример `track.update`:

```json
{"schema": "dioneya.alert/1", "seq": 49, "msg_id": "track.update:TRK-0000000700000001-1:1800000047000000",
 "type": "track.update", "tenant": "pilot1", "alert_id": "ALR-pilot1-0006651729311680",
 "time": "2027-01-15T08:00:47.000Z", "created": "2026-09-30T20:30:26.716Z",
 "track": {"track_id": "TRK-0000000700000001-1",
           "position": {"lat": 55.0119157, "lon": 37.0209397, "alt_msl_m": 410.5},
           "error": {"horizontal_m": 90.9, "vertical_m": 31.8},
           "velocity": {"speed_mps": 47.2, "course_deg": 87.5, "east_mps": 47.11, "north_mps": 2.03, "up_mps": 1.98},
           "class": {"code": "uav_piston", "label": "PISTON_UAV", "confidence": 0.784, "type": null, "f0_hz": null},
           "stations": [1, 2], "crossing_deg": 26.1, "first": "2027-01-15T08:00:10.000Z", "points": 38,
           "ended": null, "end_reason": null}}
```

Пример `bearing`:

```json
{"schema": "dioneya.alert/1", "seq": 3, "msg_id": "bearing:1:0000000700000001:1800000010500000",
 "type": "bearing", "tenant": "pilot1", "alert_id": "ALR-pilot1-0006651729311680",
 "time": "2027-01-15T08:00:10.500Z", "created": "2026-09-30T20:30:25.085Z",
 "bearing": {"station": {"station_id": 1, "lat": 55.0, "lon": 37.0, "alt_msl_m": 150.0},
             "track_event_id": "0000000700000001", "azimuth_deg": 339.37, "elevation_deg": 3.58, "sigma_deg": 1.5,
             "range_max_m": 5000.0,
             "class": {"code": "uav_piston", "label": "PISTON_UAV", "confidence": 0.784, "type": null, "f0_hz": null}}}
```

Типичная последовательность: `alert.start` (warning, одна станция) → `bearing` от станций → `alert.update` (alert,
две станции, трек) → `track.update` раз в секунду → `track.end` → `alert.end`.

## 4. Каналы

Все сообщения сначала пишутся в очередь (таблица `alert_outbox` базы сервера, хранится 30 дней) процессом, который
принимает данные станций (мост MQTT своего арендатора). Каналы читают очередь по `seq`, поэтому порядок один для всех
и после обрыва любой канал продолжает с места остановки. Доставка — «хотя бы один раз»: повторы отбрасываются по
`msg_id`.

### 4.1 HTTP-опрос

`GET /api/v1/alerts?after_seq=0&tenant=pilot1&limit=500` →
`{"schema": "dioneya.alert/1", "messages": [...], "next_after_seq": 1234}`. Следующий запрос —
`after_seq=next_after_seq`; пустой `messages` — новых нет. Доступ — учётная запись оператора с ролью `viewer`
или API-токен (`Authorization: Bearer ...`, `station/operator_auth.py`), через HTTPS-прокси сервера.

### 4.2 WebSocket

`wss://<сервер>/api/v1/alerts/stream?after_seq=<seq>&tenant=<tenant>&heartbeat_s=15` — сначала сообщения после
`after_seq` (без параметра — только новые), затем каждое новое сообщение отдельным текстовым кадром; при простое —
`heartbeat` с `seq` последнего выданного. Доступ как в 4.1.

### 4.3 Вебхук HTTPS с взаимным TLS

Сервер сам отправляет каждое сообщение `POST` на адрес потребителя: тело — сообщение, заголовки
`Content-Type: application/json`, `X-Dioneya-Schema: dioneya.alert/1`, `X-Dioneya-Seq`, `Idempotency-Key` (= `msg_id`).
Ответ 2xx — доставлено, курсор потребителя сдвигается (хранится в базе, `alert_cursors`). Любой другой ответ или
обрыв — повтор той же посылки через 1, 2, 4 ... 60 с; следующие ждут, порядок сохраняется. Потребитель отвечает 2xx
и на повтор. При простое — `heartbeat` раз в 60 с.

TLS: только `https://`, TLS 1.2+, сервер проверяет сертификат потребителя по его CA (из конфигурации) и предъявляет
свой клиентский сертификат; потребитель принимает соединения только с ним. Без CA, сертификата и ключа потребитель в
конфигурации не принимается.

Запуск (отдельный процесс рядом с сервером, та же база):

```
python -m integration.webhook --config data/webhooks.json
```

```json
{"consumers": [{"name": "platform", "url": "https://platform.example/dioneya/alerts", "tenants": ["pilot1"],
                "ca": "/run/tls/platform-ca.pem", "cert": "/run/tls/alert-client.crt.pem",
                "key": "/run/tls/alert-client.key.pem", "start": "latest"}]}
```

`tenants` пуст — все арендаторы; `start` — с чего начинает новый потребитель: `latest` (только новые) или
`earliest` (вся очередь). Для compose — сервис с командой выше, томами `../data:/app/data` и `./tls:/run/tls:ro`.

### 4.4 Дальше

- подписка MQTT: те же сообщения в топик арендатора на брокере, доступ по сертификату потребителя (ACL);
- адаптер EGTS для Платформы — отдельным процессом-потребителем очереди, когда придёт спецификация Платформы.

## 5. Проверка

`server/tests/test_alert_api.py`: последовательность сообщений через мост (начало, линии пеленгов до трека, не чаще
1 Гц, повышение уровня, точки трека по времени и по истинной траектории, повторная доставка без новых сообщений,
конец трека и тревоги по одному разу, новая тревога после конца), пеленги без доверенного времени, отказ
производителя не останавливает приём, две цели одновременно (контроль: одинаковый класс даёт ложную пару; разный
класс или основная частота — два верных трека), HTTP-опрос по страницам и по арендатору, WebSocket (очередь, живые
сообщения, heartbeat), вебхук через HTTPS с взаимным TLS (порядок, повтор после 503, заголовки, сертификат клиента
у получателя, продолжение после перезапуска, heartbeat, фильтр арендатора, отказ при чужом CA и без клиентского
сертификата, только HTTPS), конфигурация. Все сообщения проверяются по JSON-схеме.
