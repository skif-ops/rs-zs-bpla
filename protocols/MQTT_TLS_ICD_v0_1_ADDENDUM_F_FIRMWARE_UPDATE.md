# ICD GSM/LTE MQTT/TLS v0.1 — Addendum F: обновление прошивки STM32 по воздуху (2026-09-30)

Статус: DRAFT. Команда 5 обновляет приложение STM32U585 станции через MQTT без выезда. Образ подписан отдельным
офлайн-ключом выпуска (не ключом команд), принимается в неактивный банк флеш-памяти, запускается переключением банков и
подтверждается работой; неподтверждённый образ откатывается сам. Конверт §2.1, подпись команды, TTL, журнал и ACK §2.2 —
без изменений. Обновление nRF52840 по-прежнему идёт через слот NOR (ICD BLE v0.3, аддендум C.6); доставка его образа
этим путём — следующий шаг (цель 2 зарезервирована).

## 1. Команда

| Код | Имя | Ключ 7 (payload) |
|---:|---|---|
| 5 | `CMD_UPDATE_FIRMWARE` | `{0: bstr(≤96) манифест, 1: bstr(8) key ID ключа выпуска, 2: bstr(64) подпись выпуска}` |

Отпечаток журнала — SHA-256 от манифеста, key ID и подписи (тот же UUID с другим выпуском — конфликт).

### 1.1 Манифест выпуска

Канонический CBOR, ровно пять ключей:

| Ключ | Поле | Кодирование |
|---:|---|---|
| 0 | schema | uint, 1 |
| 1 | target | uint: 1 — приложение STM32U585 EVT-PRE-20; 2 — nRF52840 (зарезервировано) |
| 2 | version | uint32 ≥ 1, монотонный номер сборки |
| 3 | size | uint32, байт образа (1..ёмкость банка) |
| 4 | sha256 | bstr(32), SHA-256 всего образа |

Подпись выпуска — Ed25519 над `"DIO-FW-V1"` (9 байт ASCII) ‖ байты манифеста. Key ID — первые 8 байт SHA-256 сырого
публичного ключа (как §2.1). Публичные ключи выпуска вшиты в прошивку при сборке
(`-DZS_FW_RELEASE_PUBLIC_KEYS=<hex>[,<hex>]`, до двух); прошивка без ключа выпуска отвечает на команду `REJECTED` 1.
Сервер команд ключом выпуска не владеет: компрометация ключа команд не даёт поставить чужой образ.

### 1.2 Информационный блок образа

По смещению 0x400 от начала образа (сразу за таблицей векторов, секция `.fw_info`) — 32 байта little-endian:
`magic "DIOF"` (0x464F4944), `format` u16 = 1, `target` u16, `version` u32, 20 нулевых байт. Станция берёт из него
собственную версию и версию второго банка; после приёма target и version блока обязаны совпасть с манифестом.

## 2. Передача образа

| Topic | Направление | QoS | Payload |
|---|---|---:|---|
| `zs/v1/{tenant}/{station_id}/fwreq` | station -> server | 1 | `{0: 1, 1: 8, 2: station_id, 3: command_id bstr(16), 4: offset uint32, 5: length 1..1024}` |
| `zs/v1/{tenant}/{station_id}/fw` | server -> station | 0 | `{0: 1, 1: 9, 2: station_id, 3: command_id bstr(16), 4: offset uint32, 5: data bstr(length)}` |

Станция запрашивает куски по порядку, по одному (stop-and-wait); кусок — 1024 байта (последний короче). `fw` публикуется
с QoS 0: потерянный кусок станция запрашивает повторно через 15 с, очередь брокера для офлайн-станции не копит куски.
Подписка на `fw` делается только на время загрузки; кусок с чужим `command_id`, не тем смещением или не той длиной
станция пропускает. Восемь таймаутов подряд — загрузка приостанавливается до следующей сессии; три сессии подряд без
единого принятого куска — `FAILED` 4.

Сервер отвечает на `fwreq` только если `command_id` — его `CMD_UPDATE_FIRMWARE` этой станции без ACK, созданный не
раньше 24 ч назад, образ этого выпуска есть в хранилище выпусков и `offset + length` не выходит за образ. Иначе запрос
отбрасывается молча (станция уйдёт в таймауты и `FAILED` 4).

Прогресс загрузки живёт в RAM станции: перезагрузка посреди загрузки оставляет команду `ACCEPTED` без ACK; повторная
доставка той же команды (в пределах TTL) начинает загрузку заново, после TTL оператор ставит новую команду.

## 3. Станция

Банки STM32U585 по 1 MiB; приложение линкуется на 0x08000000 и занимает не больше 1016 KiB; последняя страница банка
(8 KiB, 0x080FE000 в карте активного банка) — запись загрузки. Неактивный банк всегда виден по 0x08100000.

| Шаг | Что происходит | ACK |
|---|---|---|
| проверка | ключ выпуска известен, подпись верна, target совпадает, version > текущей, size ≤ 1016 KiB, другая загрузка не идёт, текущий образ подтверждён | `REJECTED` 1 нет ключа выпуска / нет поддержки, 2 манифест или подпись, 3 target, 4 версия не новее, 5 размер, 6 идёт другое обновление, 7 текущий образ ещё на испытании |
| приём | стирание неактивного банка (и его страницы записи), куски программируются квадрословами по мере прихода | — |
| проверка образа | SHA-256 записанного образа (чтение из флеша) и блок `.fw_info` | `FAILED` 1 флеш, 2 SHA-256, 3 блок `.fw_info` не совпал |
| готово | `OK`, detail — число принятых кусков | `OK` |
| установка | после подтверждения брокером ACK: в страницу записи нового банка пишется «испытание» (версия, прежняя версия), SWAP_BANK переключается, сброс | — |

Испытание. Ранний загрузочный страж (`app_fw_boot_guard`, сразу после настройки тактирования, до периферии и задач)
читает запись своего банка:

- записи нет, образ подтверждён или откатан — обычный запуск;
- «испытание» и попыток меньше 3 — пишет отметку попытки, запускает IWDG сразу (~32 с) и продолжает;
- три попытки без подтверждения — пишет отметку отката, возвращает SWAP_BANK и сбрасывает: снова работает прежний образ.

Подтверждение — самотест прошёл и сессия S3 завершилась (heartbeat у брокера). Не подтверждённый за 30 мин образ
перезагружается (это следующая попытка). Отметки — отдельные квадрослова страницы записи (программируются один раз
после стирания, без стирания страницы; обрыв питания не оставляет полузаписанной отметки, CRC32 в каждой).

Heartbeat (карта детектора, аддендум C): ключ 18 `fw_version` — версия работающего образа; ключ 19 `fw_state` —
0 idle, 1 загрузка, 2 ждёт установки, 3 испытание, 4 откат (во втором банке лежит откатанный образ); ключ 20
`fw_other_version` — версия образа второго банка (0 — пусто). Сервер: `DetectorHealth.fw_version / fw_state /
fw_other_version`.

## 4. Сервер «Мухоед»

- Хранилище выпусков `--firmware-dir` (`ZS_FIRMWARE_DIR`): `<version>.bin` + `<version>.manifest.cbor` +
  `<version>.sig` (подпись и key ID, `station/firmware_codec.py`). Готовит их офлайн
  `python -m pki.cli fw-sign --key <release.pem> --image <app.bin> --out <dir>` (target и version читаются из
  `.fw_info` образа, SHA-256 и размер считаются); ключ выпуска — `python -m pki.cli fw-release-key --out <release.pem>` (PKCS#8 PEM,
  `0600`, публичный ключ печатается для `-DZS_FW_RELEASE_PUBLIC_KEYS`).
- Оператор: `POST /api/v1/stations/{id}/firmware-update` `{"version": N}` (роль `operator`) ставит команду 5 с манифестом
  и подписью выпуска N; `GET /api/v1/firmware/releases` — список выпусков хранилища.
- Bridge подписывается на `+/fwreq` и отвечает кусками по правилам §2; ACL брокера: станция пишет в свой `fwreq`,
  читает свой `fw`; сервер наоборот.

## 6. Ограничения (не закрыто этим аддендумом)

- Нет защищённого загрузчика и TrustZone (инженерный профиль): подпись выпуска проверяет прежний образ до установки,
  при каждой загрузке образ не проверяется. Защита от отката к старой версии — только «version > текущей» в проверке.
- Программирование банков, option bytes (SWAP_BANK) и поведение ECC при обрыве питания посреди записи квадрослова —
  только на двойнике и в модульных тестах; на плате не проверено (HARDWARE_PENDING). Прерванная запись квадрослова
  на STM32U5 может дать ошибку ECC при чтении (NMI) — обработчик NMI для страницы записи загрузки не реализован.
- Прогресс загрузки не переживает перезагрузку (§2).
