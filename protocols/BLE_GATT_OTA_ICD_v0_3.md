# ICD BLE v0.3 — секреты станции по BLE (2026‑09‑24)

Статус: `FROZEN 2026-09-24 / STM32 + nRF52840 + ANDROID + SERVER PKI IMPLEMENTED ON THE HOST / HARDWARE CONFIRMATIONS AS IN v0.2 §8`.

v0.3 снимает заморозку v0.2 ради одной характеристики — доставки секретов станции с телефона в сервисном режиме.
Всё замороженное в v0.2 (`BLE_GATT_OTA_ICD_v0_2.md` §2–§7) действует без изменений; ниже — только добавление и
журнал. Изменение любого элемента v0.3 = v0.4 с записью в §9 и `PROTOCOL_VERSIONING.md`.

## 2. GATT — дополнение таблицы v0.2 §2

| id16 | характеристика | свойства | формат | статус |
|---|---|---|---|---|
| 0x0206 | station_secrets | read/write/notify (authenticated) | запись — CBOR‑патч §3.1; чтение/notify — карта присутствия §3.2; ответ на запись — статус B.3 | заморожено v0.3 |

Кадрирование B.2, один WRITE_STATUS на запись, после успешной записи станция уведомляет картой присутствия.
nRF52840: характеристика добавлена в сервис 0x0200 (`gatt.c`), мост прозрачный (C.1); кэш чтения +1 слот.

## 3. Данные

### 3.1 Запись: CBOR‑патч секретов (сливается с хранимой записью)

| ключ | тип | значение |
|---:|---|---|
| 1 | bstr(32) | ключ инженера B.9 (v0.2 §4) |
| 2 | tstr | ICCID SIM‑слота 1, 18–22 цифры; пустая строка снимает |
| 3 | tstr | ICCID SIM‑слота 2 |
| 4 | bstr(32) | публичный ключ Ed25519 подписи команд (`MQTT_TLS_ICD_v0_1.md` §2.1, raw) |
| 5 | bool | `true` — стереть всю запись (остальные ключи игнорируются) |

Неизвестный ключ, неверная длина ключа, неверный ICCID, не‑map, хвост — статус 0x01 REJECTED_VALIDATION без
изменения записи. Значения нигде не читаются обратно.

### 3.2 Чтение / notify: карта присутствия

`{0: version uint, 1: bool ключ инженера, 2: bool iccid1, 3: bool iccid2, 4: bool ключ команд}` — 11 байт; на
пустой станции `version = 0`, все `false`. Отдаётся при подключении (LINK_STATE), по READ_REQUEST и после каждой
успешной записи.

### 3.3 Хранение на станции

`zs_station_secrets`: двухслотовая запись в NOR (2 блока @0x03F79000 перед boot counter), формат `ZSSECR01 |
version | flags | engineer_key | iccid1 | iccid2 | command_key | CRC32`; commit в неактивный слот, побеждает новейшая
валидная запись. Применение: ключ инженера — в `zs_ipc_service` (роль B.9 на следующем челлендже), ICCID — в
comms (dual SIM), ключ команд — зарезервирован для trust‑адаптера команд.

## 4. Политика доступа (дополнение v0.2 §4)

- Только сервисный режим (иначе 0x03) и защищённый линк LESC (иначе 0x04).
- **Пустая станция** (записи нет) принимает первый патч от установщика — это шаг commissioning.
- **Заполненная станция** меняется только с ролью engineer (B.9, ключом, который на ней уже лежит); установщику —
  0x04. Смена ключа инженера в этом же патче допустима: новый ключ действует со следующего челленджа, текущая
  роль линка сохраняется.
- Каждая попытка аудируется через `zs_commissioning_audit_io_t`: `SECRETS_WRITE`/`SECRETS_CLEAR`, фазы
  INTENT → COMMITTED (с версией записи) или REJECTED (`POLICY_ROLE_REQUIRED`, `INVALID_RECORD`,
  `STORAGE_IO_ERROR`), роль сеанса в событии.
- Отсутствие NOR‑хранилища (RAM‑фолбэк стенда) — 0x05 STORAGE_ERROR.

## 5. Источник секретов

`muhoed-pki station-secrets <serial> --out <dir> [--iccid1 …] [--iccid2 …] [--command-signing-key <pem>]
[--no-engineer-key] [--to <кому>]` → `<serial>.station-secrets.json`:
`{"serial", "context": "DIO-SECRETS-V1", "engineer_key_hex"?, "iccid1"?, "iccid2"?, "command_public_key_hex"?,
"command_key_id_hex"?}`; экспорт аудируется в реестре (`station_secrets: exported to <кому>: <поля>`). Файл
передаётся установщику вне этикетки и удаляется после записи; приложение ничего из него не сохраняет
(`StationSecretsBundle`, `StationSecretsController`). Ключ инженера для собственного челленджа инженер получает
отдельно (`engineer-key`, `EngineerKeyStore`).

## 6. Стенд

Консоль STM32: `secrets` — присутствие/версия, `engkey`/`simiccid` — запись отдельных полей (коммит в NOR),
`secrets clear`. Запись по BLE и с консоли попадают в одну запись; консольные команды остаются для стенда.

## 8. Подтверждения на железе — как в v0.2 §8, плюс

6. Запись 0x0206 с телефона на пустую станцию (установщик) и отказ повторной записи без роли инженера; чтение
   присутствия после переподключения.

## 9. Журнал изменений v0.2 → v0.3

- добавлена 0x0206 station_secrets (патч/присутствие/политика/аудит), nRF‑сервис 0x0200 расширен;
- новые операции аудита `SECRETS_WRITE`, `SECRETS_CLEAR` (`zs_commissioning_operation_t`);
- реестр «Мухоеда»: `station-secrets` экспорт; Android: `StationSecretsBundle`/`StationSecretsController`, диалог
  «Секреты станции»;
- всё остальное — без изменений; status/gnss_integrity/log/OTA STM32 остаются зарезервированными (v0.4+).
