# ICD GSM/LTE MQTT/TLS v0.1 — Addendum E: удалённая ротация ключа подписи команд (2026-09-27)

Статус: DRAFT. Реализует обещание §4 («ротация использует новый key ID и период явного доверия к старому и новому
public key») без выезда к станции. Конверт §2.1, подпись Ed25519, TTL, журнал и ACK §2.2 — без изменений; добавлены
код команды 4, «следующий» ключ в записи секретов станции и два ключа в heartbeat.

## 1. Команда

| Код | Имя | Ключ 7 (payload) |
|---:|---|---|
| 4 | `CMD_ROTATE_COMMAND_KEY` | `{0: bstr(32)}` — сырой публичный ключ Ed25519, которым сервер будет подписывать дальше |

Подписывается любым ключом, которому станция доверяет. Отпечаток журнала — SHA-256 нового ключа (переиспользование
UUID с другим ключом — конфликт, как для остальных команд).

## 2. Станция

Запись секретов (`zs_station_secrets`, NOR, два слота) хранит текущий ключ и — пока ротация не завершена —
следующий. Формат `ZSSECR02` (164 байта): поля v1 до 126, следующий ключ [126..158), флаг bit4, CRC32 [0..160) в
160. Запись v1 (`ZSSECR01`, 132 байта) читается как раньше; первый же commit переписывает её в v2.

| Шаг | Что происходит | ACK |
|---|---|---|
| `CMD_ROTATE_COMMAND_KEY(K2)`, подписан K1 | K2 записан как следующий, доверяются **оба** (набор доверия перезагружается сразу, в той же сессии) | `OK`; тот же K2 повторно — `OK` без записи |
| | K2 нулевой или уже текущий | `REJECTED` 2 |
| | записи секретов нет | `REJECTED` 3 |
| | commit NOR не прошёл проверку (остаётся прежний набор) | `FAILED` 1 |
| любая команда, проверенная ключом K2 | до исполнения: K2 становится текущим, K1 удаляется из записи и из набора доверия | как у самой команды |

Повышение по первой команде с K2 — доказательство, что сервер владеет K2. Пока его нет, станция отвечает и на K1:
сервер, потерявший K2 до первой команды, не теряет станцию. Прошивка без аддендума отвечает `REJECTED` 1 («не
реализовано»).

Восстановление: запись ключа команд инженером по BLE (ICD BLE v0.3, 0x0206, ключ 4) заменяет текущий ключ и
**сбрасывает** следующий — выход из неудачной ротации на месте.

Heartbeat (карта детектора, ключ 13 §3.2; аддендум C): ключ 16 `command_key_id` — id текущего ключа, ключ 17
`command_next_key_id` — id следующего (0 — нет); оба uint64 (первые 8 байт SHA-256 публичного ключа, big-endian —
тот же key ID §2.1). Сервер: `DetectorHealth.command_key_id/command_next_key_id` (hex или `null`).

## 3. Сервер «Мухоед»

`station/mqtt_bridge.py --command-next-signing-key <pem>` (или `ZS_COMMAND_NEXT_SIGNING_KEY`) рядом с
`--command-signing-key` включает `CommandKeyring`: для каждой команды bridge выбирает ключ по состоянию станции —
следующий, если последний heartbeat станции называет его (текущим или следующим) или станция подтвердила
`CMD_ROTATE_COMMAND_KEY` с ним `OK` позже своего последнего heartbeat; иначе текущий. Ключ выбирается при каждой
публикации (повтор команды может уйти уже с новым ключом: отпечаток журнала key ID не включает).

Оператор: `POST /api/v1/stations/{id}/command-key-rotation` `{"public_key": "<64 hex>"}` (роль `operator`) ставит
команду в очередь; публичный ключ bridge печатает при старте (`command key rotation: current …, next … (public key …)`).

Порядок ротации парка:
1. Сгенерировать K2 (Ed25519 PKCS#8 PEM, `0600`), перезапустить bridge с `--command-next-signing-key K2`.
2. Для каждой станции — `command-key-rotation` с публичным ключом K2. Ход виден в `/api/v1/stations`
   (`detector.command_key_id / command_next_key_id`).
3. Когда все станции сообщают K2 текущим, перезапустить bridge с `--command-signing-key K2` без next-ключа; K1
   уничтожить. Станции, не вышедшие на связь, до этого момента продолжают принимать K1.

Компрометация K1: злоумышленник с K1 может провести свою ротацию и вытеснить сервер — это не хуже самой компрометации
(K1 и так даёт все команды). Выход — BLE-запись ключа инженером (§2).

  подтверждённая ротация, сброс инженером), bridge подписывает каждую станцию своим ключом, маршрут оператора.
- Двойник, сценарий 5 `server/tools/test_station_twin_e2e.py`: ротация в загрузочной сессии, следующая команда уже

  без ACK, следующий heartbeat сообщает K2 текущим.
