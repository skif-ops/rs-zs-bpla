# Cellular connectivity baseline — EVT-PRE-20

## Решение для пилота

Выделенный/private APN, статический IP и операторский API не являются обязательными. Допускается обычная SIM с публичным APN, если тариф и сеть поддерживают фактический radio access mode установленного модема.

Пилотные профили создаются для МТС, МегаФон, Билайн, T2/Tele2 и SIM, предоставленной оператором ГЛОНАСС. Фактический underlying carrier, тариф, APN и разрешённые RAT фиксируются для каждого ICCID.

## Сетевая модель

- станция всегда является инициатором соединения;
- основной транспорт — MQTT over TLS 1.2+;
- предпочтительный порт — 443, допустимый альтернативный — 8883;
- резерв — HTTPS over TLS через порт 443;
- входящие TCP/UDP-соединения к станции отсутствуют;
- работа за CGNAT обязательна;
- команды сервер → станция передаются через уже установленную MQTT-сессию;
- при недоступности сети события сохраняются локально с sequence/event_id и отправляются после восстановления связи;
- смена публичного APN на private APN не должна требовать изменения hardware или перепрошивки приложения;
- `PCB-MAIN` содержит два nano-SIM слота в режиме Dual SIM Single Standby;
- одновременно активна только одна SIM;
- переключение SIM выполняется только после штатного выключения BG95;
- профиль APN и слот могут меняться автоматически по ограниченной политике failover либо вручную через авторизованный BLE/mTLS канал.

## Параметры профиля SIM/APN

Конфигурация хранит: operator profile id, APN mode `PUBLIC`/`PRIVATE`, APN, authentication mode, secret references при необходимости, preferred RAT, roaming policy, PIN policy, DNS policy, attach timeout, retry/backoff, daily byte budget, номер слота и ICCID reference. Секреты не хранятся в GitHub.

Для каждой SIM разрешается несколько профилей APN. Private APN работает только при наличии соответствующей услуги оператора. Ошибка private APN не должна блокировать переход на разрешённый public APN или вторую SIM.

## Проверка до закупки двадцати SIM

1. Проверить регистрацию тестовой SIM каждого заявленного оператора во всех разрешённых RAT модема.
2. Проверить DNS и TLS к пилотному endpoint.
3. Проверить MQTT publish/subscribe не менее 24 часов.
4. Проверить восстановление после потери сети, питания и исчерпания PDP context.
5. Проверить ограничения тарифа на IoT-модем, roaming и объём трафика.
6. Зафиксировать ICCID, операторский профиль и результат без сохранения PIN/ключей в открытом виде.
7. Проверить обе SIM в обоих слотах и подтвердить отсутствие зависимости результата от номера слота.
8. Выполнить не менее 100 циклов безопасного переключения слотов с чтением ICCID и восстановлением очереди.
9. Проверить переход `public APN -> private APN -> public APN`, если private APN предоставлен оператором.

## Gate

Профиль получает `PASS` только после прикрепления modem log, server log, traffic counter и записи о восстановлении store-and-forward. До этого статус `OPEN / NOT RUN`.
