# ICD GSM/LTE MQTT/TLS v0.1 — Addendum I: пакет модели классификатора отдельно от прошивки (2026-09-30)

Статус: DRAFT. Переобученная модель станции (ближайший центроид по 43 признакам, `zs_classifier`) доставляется
подписанным пакетом без выпуска прошивки и без перезагрузки. Доставка — та же команда 5 и те же сообщения `fwreq`/`fw`,
что для образа (аддендум F), с манифестом цели 3. Конверт, подпись команды, TTL, журнал и ACK — без изменений.

## 1. Команда и манифест

Команда 5 `CMD_UPDATE_FIRMWARE` с полями аддендума F §1. Манифест — тот же канонический CBOR из пяти ключей, `target = 3`
(модель станции), `version` — номер пакета (uint32 ≥ 1, совпадает с версией в заголовке пакета), `size` — байт пакета,
`sha256` — SHA-256 пакета. Подпись — тем же офлайн-ключом выпуска, Ed25519 над `"DIO-FW-V1"` ‖ манифест: отдельного
ключа для моделей нет, станция проверяет пакет ключами выпуска, вшитыми в прошивку.

Станция выбирает путь по цели манифеста до всех проверок: цель 3 — пакет модели, иначе — образ (аддендум F).

## 2. Пакет «DIOM», формат 1

Little-endian, выравнивание 4 байта:

| Смещение | Поле | Значение |
|---:|---|---|
| 0 | magic u32 | `"DIOM"` (0x4D4F4944) |
| 4 | format u16 | 1 |
| 6 | feature_count u16 | 43 |
| 8 | class_count u16 | 1..96 (n) |
| 10 | reserved u16 | 0 |
| 12 | version u32 | ≥ 1, равна версии манифеста |
| 16 | feature_set u32 | 1 — 43 признака `zs_dsp` в порядке `server/tools/golden/feature_order.txt` |
| 20 | reserved | 12 нулевых байт |
| 32 | mean | f32[43] |
| | std | f32[43] |
| | class_id | u8[n], дополнено нулями до кратного 4 |
| | radius | f32[n] |
| | centroid | f32[n][43] |

Размер ровно `32 + 344 + ((n+3)&~3) + 4n + 172n` (один класс — 556 байт, 96 классов — 17 368). Все числа конечные,
`std ≥ 0`, `radius > 0`, коды классов — значения `zs_class_id_t` кроме UNKNOWN (1..3, 10..18). Предсказание не меняется:
z-оценка `(f − mean)/(std + 1e-6)`, евклидово расстояние до центроидов, уверенность `1 − d/(1.5·radius)` в [0, 1].
Пакет, собранный из встроенной таблицы (`zs_model_centroids.h`), даёт те же ответы бит в бит (проверяет
`firmware/tests/test_model.c`).

## 3. Станция

**Проверка команды** (`zs_fw_model_check`, детали REJECTED как в аддендуме F §3):

| Деталь | Когда |
|---:|---|
| 1 | нет ключей выпуска или хранилища моделей |
| 2 | манифест не декодируется, неизвестный key ID, подпись не сходится |
| 3 | цель не 3 |
| 4 | версия равна версии активной модели (откат — повторный выпуск старого пакета — разрешён) |
| 5 | пакет больше слота (60 КиБ) или меньше пакета из одного класса |
| 6 | идёт другая загрузка образа или модели |

**Хранилище** (`zs_model_store`): область моделей во внешней NOR, два слота по 16 блоков 4 КиБ (блок заголовка и 60 КиБ
пакета), между исходящей очередью событий и секретами станции (`archive | journal | outbox | model ×2 | secrets ×2 |
boot counter | nrf image | config ×2 | installation ×2`); адреса хранилищ выше неё не изменились. Загрузка идёт в
неактивный слот: сначала стирается его блок заголовка, затем пакет пишется движком аддендума F. После чтения SHA-256
движок вызывает проверку содержимого (`validate`): пакет разбирается полностью, его версия должна совпасть с манифестом,
иначе FAILED 3 (для образа на этом месте проверяется `.fw_info`). ACK OK — detail = число фрагментов.

**Включение.** Только когда ACK OK принят брокером, в блок заголовка слота пишется запись 64 байта:
`"DIOMSLT1" | seq u32 | version u32 | size u32 | SHA-256 пакета | 8 нулевых байт | check u32` (check — первые 4 байта
SHA-256 предыдущих 60 байт), seq на единицу больше активного. Затем пакет загружается в ОЗУ и становится активной
моделью без перезагрузки. При старте активен действительный слот с наибольшим seq, пакет которого сходится со своим
SHA-256; оборванная загрузка, потеря питания до записи заголовка или испорченный пакет оставляют прежний слот, а без
действительных слотов — встроенную модель.

**Модель в ОЗУ.** Одна таблица (≈17 КиБ для 96 классов) под счётчиком последовательности: во время записи таблицы
окна конвейера классифицируются встроенной моделью, после — новой; наполовину записанная таблица не используется. Пакет
сначала проверяется целиком без записи, неудачная загрузка оставляет прежнюю модель (при сбое чтения посреди записи —
встроенную).

**Телеметрия.** Ключ 9 heartbeat (`model_ver`): `c<классов>` — встроенная модель (сейчас `c46`), `m<версия>` — пакет.
Ключ 19 (состояние обновления прошивки) загрузку модели не показывает.

## 4. Сервер

- Пакет: `python tools/export_station_model.py --package m<N>.diom --version N` (или `station/model_codec.encode_model`).
- Подпись (офлайн): `python -m pki.cli model-sign --key release.pem --model m<N>.diom --out <models>`; хранилище
  устроено как хранилище выпусков (`<N>.bin`, `<N>.manifest.cbor`, `<N>.sig`), при каждом чтении размер и SHA-256
  пакета сверяются с манифестом, манифест другой цели отвергается.
- Мост: `--model-dir` (`ZS_MODEL_DIR`, по умолчанию `data/models`); `fwreq` команды с манифестом цели 3 обслуживается из
  хранилища моделей, остальные правила аддендума F §2 те же.
- Оператор: `POST /api/v1/stations/{id}/model-update` `{"version": N}` ставит команду 5 с манифестом и подписью пакета N;
  `GET /api/v1/models/releases` — список пакетов (версия, размер, число классов, SHA-256, key ID).
