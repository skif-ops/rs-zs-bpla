# ICD LoRa backup transport v0.1 — Addendum A: compact single-hop event uplink (2026-09-24)

Статус: DRAFT для цифрового двойника и стенда. Не заменяет §3 основного ICD (AEAD, relay-hops, фрагментация
остаются до security review); региональный гейт §2 (`tx_enabled: false` до подписанного профиля и закрытия RF gate)
действует без изменений — передатчик на железе не включается этим аддендумом.

## 1. Назначение

Когда GSM-канал помечен деградированным (три подряд сессии S3, завершённые сторожевым таймером), станция передаёт
события P0 из outbox одним LoRa-кадром на шлюз в прямой видимости (один хоп). Шлюз пересылает событие в «Мухоед»
и **только после приёма сервером** отвечает ACK. Семантика outbox та же, что по MQTT: `delivered` только по
application-квитанции; до ACK событие остаётся в outbox и повторяется с backoff.

## 2. Кадры (little-endian)

Событие (тип 0x10, 38 Б):

| смещ. | поле | размер | примечание |
|---:|---|---:|---|
| 0 | type | 1 | 0x10 |
| 1 | profile_id | 2 | id подписанного регионального профиля (RU868/EU868); кадр с чужим профилем отбрасывается |
| 3 | station_id | 4 | |
| 7 | boot_id | 4 | event_id = (boot_id << 32) \| seq_no — тот же id, что в CBOR-событии |
| 11 | seq_no | 4 | |
| 15 | time_s | 4 | unix-секунды события |
| 19 | time_ms | 2 | |
| 21 | class_id | 1 | |
| 22 | confidence | 1 | 0..255 |
| 23 | presence_level | 1 | 0 none, 1 suspect, 2 engine, 3 confirmed |
| 24 | f0_hz | 2 | |
| 26 | battery_mv | 2 | |
| 28 | battery_pct | 1 | |
| 29 | flags | 1 | bit0 retry, bit1 gsm_degraded |
| 30 | tag | 8 | HMAC-SHA256(key, bytes[0..30))[0..8] |

ACK (тип 0x90, 21 Б): `type, station_id u32, boot_id u32, seq_no u32, tag[8] = HMAC-SHA256(key, bytes[0..13) || "ACK")[0..8]`.

Ключ: `key = SHA-256("DIO-LORA-V1" || engineer_key)` — ключ инженера станции есть у обеих сторон (запись секретов
станции, реестр сервера). Шифрования полезной нагрузки нет: поля (класс, время, батарея) не секретны, station_id
публичен; защита — от подделки и повтора (dedup по event_id на сервере, окно повторов на шлюзе).

Кросс-вектор (ключ инженера a0..bf, profile 1, station 17, boot 5, seq 42, t = 1800000123.456, class 3, conf 188,
level 3, f0 185, 13200 мВ, 80 %, flags 0x02):
`10010011000000050000002a0000007bd2496bc80103bc03b90090335002458f74816ba29b5f`;
ACK: `9011000000050000002a0000001139d77b78a4d704`. Проверяется `firmware/tests/test_lora_frame.c` и `server/tests/test_lora_codec.py`.

## 3. Радио и бюджет

SF9 / 125 кГц / CR 4/5, explicit header, CRC: событие 268 мс, ACK 186 мс (`zs_lora_airtime_ms`, AN1200.13). Duty-cycle
1 % → 36 с/ч → ≈ 75 событий/ч с ACK. Окно приёма ACK после передачи: 3 с (класс-A). Повтор при отсутствии ACK: backoff
30 с → 60 → … ≤ 10 мин, не чаще бюджета duty-cycle. Частоты — только из `config/lora/RU868.yaml` (§2 основного ICD).

## 4. Шлюз

Принимает кадр, проверяет profile_id/tag/окно повторов, преобразует в `DetectionMessage` (schema 4, поля, которых нет
в кадре, — отсутствуют/по умолчанию), отправляет серверу по обычному пути; после успешного приёма сервером шлёт ACK.
Дедупликация на сервере — по event_id, так что событие, ушедшее и по LoRa, и позже по GSM, учитывается один раз.

## 5. Реализация

Кодек: `firmware/src/zs_lora_frame.c`, `server/station/lora_codec.py`. Транспорт станции (`zs_lora_uplink`), шлюз в
сервере-двойнике и сценарий «GSM пропал → LoRa → GSM вернулся» — фаза 2 цифрового двойника.
