# EVT-PRE-20 — диагностический импорт KiCad в Altium Designer

Дата: 2026-10-14. Ветка: `evt-pre-20`. Altium Designer 26.10.1.5 с установленным KiCad Importer.

**NOT FOR MANUFACTURE.** В этом каталоге находятся реальные файлы Altium, полученные пробным импортом `PCB-MAIN`, `PCB-PWR` и `PCB-MIC`. Импорт завершился с ошибками, электрическая и геометрическая эквивалентность не доказана. Эти файлы предназначены только для разбора и исправления переноса. `OutJob`, Gerber, drill, BOM, Pick&Place и производственный ZIP из них не выпускались.

Исходные 76 KiCad-файлов в `hardware/kicad/native/` не изменялись и не удалялись; их Git-история сохранена. MAIN и PWR импортированы из полной изолированной копии дерева KiCad на диске F, включая относительные связи PWR с библиотекой MAIN. MIC первоначально импортирована из рабочей Git-копии, после чего только созданный Altium-каталог перемещён отдельно. `git diff` по KiCad-файлам пуст.

## Результат импорта

| Плата | Созданные документы | Предупреждения анализа схемы | Предупреждения анализа платы | Ошибки импорта платы |
| --- | --- | ---: | ---: | ---: |
| PCB-MAIN | `PrjPcb`, 10 `SchDoc`, `PcbDoc`, 2 `SchLib` | 336 | 891 | 873 |
| PCB-PWR | `PrjPcb`, 5 `SchDoc`, `PcbDoc`, 2 `SchLib` | 52 | 2115 в мастере; 2117 в итоговом журнале | 677 |
| PCB-MIC | `PrjPcb`, 1 `SchDoc`, `PcbDoc`, 2 `SchLib` | 0 | 275 | 48 |

Все ошибки импорта платы имеют вид `Import is not implemented for: KiCadLib.PCB.PCBLine`. Журналы `*.PcbDoc.LOG` и `*.SchLib.LOG` сохранены рядом с документами. Среди предупреждений есть пропущенные поля `stroke`, `thermal_bridge_angle`, `uuid`, `locked`, а также автоматически присвоенные имена некоторым безымянным контактным площадкам. Нельзя считать эти сообщения косметическими без проверки соответствующих объектов.

Для PCB-PWR мастер неверно предложил отображать `F.Mask` в `Mid Layer1`, `B.Cu` в `Mid Layer2`, `B.Mask` в `Mid Layer3` и `F.SilkS` в `Mid Layer5`. Снимок экрана: [PCB-PWR/layer-map-preview.png](PCB-PWR/layer-map-preview.png). Такой стек слоёв нельзя использовать для изготовления. Для PCB-MAIN на видимых строках мастер сопоставил `F.Cu` с Top, `In1.Cu`–`In4.Cu` с Mid Layer1–4 и `B.Cu` с Bottom; это только предварительный осмотр, а не проверка всего стека: [PCB-MAIN/layer-map-preview.png](PCB-MAIN/layer-map-preview.png).

KiCad-файл PCB-MAIN имеет версию формата `20221018`; PCB-PWR и PCB-MIC — `20241229` (KiCad 9). [Таблица совместимости Altium](https://www.altium.com/documentation/altium-designer/design-tools-interfacing) указывает поддержку KiCad до 8.x, что согласуется с наблюдаемыми ошибками KiCad 9. Это объяснение вероятное; только повторный импорт поддерживаемого формата и сравнение объектов могут подтвердить причину каждого дефекта.

## Контрольные проверки

Эталонные KiCad XML netlist содержат MAIN 248 компонентов / 355 цепей / 1074 узла, PWR 62 / 32 / 161, MIC 4 / 9 / 19. Полная сверка `refdes–pin–net`, footprint/pad, контура и координат с Altium не пройдена. На исходных KiCad-проектах выполнены ERC и DRC со сверкой платы и схемы; подробные результаты находятся в [исходном аудите](../EVT_PRE_20_KICAD_BASELINE_AUDIT_2026-10-14.md). Источник уже имеет открытые DRC/parity нарушения: MAIN 203 ошибки DRC, 499 неподключённых элементов и 601 замечание parity; PWR 251 замечание parity; MIC 8 ошибок DRC и 55 замечаний parity. ERC сообщил 0 нарушений на всех трёх корневых схемах.

Altium compile/ERC, DRC, сравнение RF-цепей и силовых цепей, проверка стеков/импедансов/переходных отверстий, сборочные варианты и выходные файлы не подтверждены. Запуск DRC на ошибочно отображённых слоях PWR или на платах с неперенесёнными `PCBLine` не может закрыть конверсионный gate. Исходный статус `manufacturing_release=false` остаётся в силе.

## Структура и связи

Каждый `*.PrjPcb` ссылается на соседние `SchDoc`, `PcbDoc`, `SchLib` и журналы относительными `DocumentPath`; эти файлы включены здесь и скопированы с проверкой SHA-256. Временные `History/` и `*_template.SCHDOT` не включены, так как они не являются ссылками проекта. Полные сырые пробные каталоги остаются локально на F в `altium-import-trial/`.

Только после этого создавать `OutJob` и полный производственный архив.
